# M3 配置与质量验收报告

> 日期：2026-08-10
> 版本：`0.3.0`
> 结论：M3 通过

## 1. 验收范围

M3 覆盖 Wallpaper Engine 属性、桌面调试面板、宿主与临时配置优先级、多档渲染/模型纹理、低 FPS 时间一致性、常见宽高比、高 DPI、动态尺寸切换、最重画质组合性能以及 WebGL 上下文恢复。

字幕位置和缩放已明确移出首发范围，不属于 M3/M4 门槛，将在首发后的更新版本实现。

## 2. 测试环境

- 系统：Windows，逻辑桌面 2560×1440，GPU 当前输出 3840×2160，系统缩放约 150%；
- GPU：NVIDIA GeForce RTX 4070 Ti SUPER，16,376 MiB，驱动 `32.0.15.9186`；
- 实际显示器：1 台；
- Wallpaper Engine：本机安装的 64 位网页宿主；
- 浏览器 WebGL 测试：显式视口测试时 `devicePixelRatio ≈ 1.75`；
- 模型：Spine 3.8.99，2K/4K/8K 三档纹理；
- 构建：Vite 离线产物，无远程运行依赖。

## 3. 显示与尺寸切换

所有测试均保持 `running`，ResizeObserver 触发后画布按当前 CSS 宽高比重新计算，没有拉伸、错误阶段或控制台报错。

| 场景 | CSS 视口 | WebGL 内部画布 | 结果 |
| --- | ---: | ---: | --- |
| 16:10 | 731×457 | 1728×1080 | 通过 |
| 21:9 | 983×411 | 2583×1080 | 通过 |
| 双屏等效超宽 | 1463×411 | 3844×1080 | 通过 |

测试按 16:10 → 21:9 → 双宽连续切换，覆盖显示器尺寸变化时的运行路径。本机只有一块实际显示器，因此没有声称完成物理热插拔；双宽等效视口已经覆盖渲染层收到的合并宽屏尺寸，物理双屏继续由跨电脑离线包补充样本，但不阻塞 M3。

## 4. FPS 与动画时间

新增纯逻辑 `FrameLimiter` 回归测试，以 120 Hz 输入时间轴运行 10 秒，验证 15/30/60/无限制四档的输出帧数与累计动画时间。各档累计动画时间误差均小于 0.001 秒，重置后不会继承暂停前的余量。

浏览器真实渲染结果：

| FPS 上限 | 实测 FPS | 平均 CPU 提交 | 最大 CPU 提交 | 结果 |
| ---: | ---: | ---: | ---: | --- |
| 15 | 15.0 | 0.773 ms | 1.500 ms | 通过 |
| 30 | 30.0 | 0.637 ms | 1.300 ms | 通过 |
| 60 | 60.0 | 0.498 ms | 0.700 ms | 通过 |
| 无限制 | 159.9 | 0.428 ms | 0.900 ms | 通过 |

CPU 提交时间只表示 JavaScript 更新和 WebGL 命令提交，不等同于 GPU 完成时间。动画速度由累计时间测试单独保证。

## 5. 4K 渲染与 8K 纹理基线

纹理解码后的理论 RGBA8 占用：

| 档位 | 页面尺寸 | 磁盘 PNG | 解码 RGBA8 |
| --- | --- | ---: | ---: |
| 2K | 2048²、2048²、2048×1024 | 2.9 MiB | 40 MiB |
| 4K | 4096²、4096²、4096×2048 | 17.2 MiB | 160 MiB |
| 8K | 8192²、8192²、8192×4096 | 51.9 MiB | 640 MiB |

浏览器在 `3842×2160` 内部画布和 8K 纹理下保持待机状态，实测约 159.9 FPS，平均 CPU 提交 0.455 ms，最大 0.900 ms。

Wallpaper Engine 独立 `3840×2160` 窗口以 4K 渲染和 8K 纹理运行稳定阶段的系统计数：

- 6 个独立网页宿主进程；
- 工作集总计约 1378.6 MiB；
- Private Bytes 总计约 1610.6 MiB；
- Windows GPU Process Memory 专用显存约 1365.3 MiB；
- NVIDIA 全局显存相对启动前增加约 1186 MiB；
- GPU Engine 采样约 16.66%；
- 测试进程均持续响应，测试窗口正常关闭且进程组完全退出。

结论：8K 纹理可以运行，但内存和显存成本显著。首发默认继续使用 1080P 内部渲染和 4K 纹理；4K/8K 作为用户主动选择的高负载组合。

## 6. WebGL 上下文恢复

修复前没有监听 `webglcontextlost` / `webglcontextrestored`。M3 在渲染层加入以下行为：

1. 丢失时阻止默认不可恢复行为，冻结帧时间并保存动画轨道、对话与交互状态；
2. 暂停语音和 BGM，避免 GPU 恢复期间音画继续漂移；
3. 恢复时重建 shader、batcher、Spine renderer、AssetManager、atlas 和纹理；
4. 恢复动画轨道时间、当前对话条目、交互偏移和目标纹理档；
5. 重置帧时间基准并恢复音频。

入场状态测试得到 `running → loading → running`，动画仍为 `Start_Idle_01`。对话中测试得到：

- 丢失前：对话、第一句字幕、BGM 播放；
- 丢失中：对话与字幕保留，BGM/语音暂停，阶段为 `loading`；
- 恢复后：阶段回到 `running`，BGM/语音恢复，第一句结束后第二句正常触发；
- 最终：正常经过冷却回到待机。

两组测试均无警告、错误或状态机重置。

## 7. M3 结论

M3 所有首发前配置与质量项目已完成。物理双屏样本继续通过跨电脑测试包收集，但渲染层的双宽尺寸和动态调整路径已经通过，不再阻塞 M3。
