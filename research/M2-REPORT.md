## 实现范围

- 角色配置包含五组 `Talk_0N_M + Talk_0N_A` 双轨动画和 10 条事件台词；
- Spine 基础轨道 0 保持入场/待机，运动和附件覆盖分别使用轨道 1、2；
- `AnimationState` 的 `sound/*` 与 `Talk` 事件分别驱动语音和字幕，不使用手工计时器猜测触发时间；
- 30 条日语、简中、韩语 OGG 按 skeleton 逻辑 ID 映射；
- 简中和日文字幕可切换，韩语仅提供语音，因为固定来源没有韩文文本；
- 身体轻点按顺序循环五组对话；
- 身体按下后移动超过 9 CSS 像素进入视线跟随，释放时播放 `LookEnd_01_M/A`；
- 头部命中后进入抚摸姿态，拖动通过 `Touch_Point` 父锚点控制幅度，释放时播放 `PatEnd_01_M/A`；
- `intro / idle / dialogue / look / pat / cooldown` 状态机阻止冲突输入，并在结束动画及 0.55 秒冷却后回到待机；
- 页面隐藏和 Wallpaper Engine `setPaused` 均暂停渲染、当前语音和循环 BGM。

## 0.2.1 对话解锁缺陷修复

人工检查发现，首次对话后可能无法再次触发对话、视线或头部互动。根因是交互状态只等待运动轨道的 Spine `complete` 回调；当 `Talk` TrackEntry 淡出到排队的空动画时，部分运行路径以 `end` 结束，导致状态永久停留在 `dialogue`，而命中测试仅允许 `idle` 接受输入。

修复位于 Spine 状态层：

- 保存本次对话的运动 TrackEntry，只允许该实例解锁；
- 同时处理 `complete` 与 `end`，任一路径只完成一次；
- 增加“动画时长 + 0.75 秒”的看门狗，在 Runtime 未发出预期回调时安全回退；
- `playIdle` 和重新播放入场时清理 TrackEntry 与看门狗状态。

回归测试在同一页面、不刷新且不强制复位的条件下完成：第一组对话自然结束后依次完成视线拖动、头部拖动和第二组对话；第二组自然结束后第三组对话再次启动。每次结束均回到 `idle`，浏览器控制台仍为 0 条 warning / error。

## 0.2.4 首次播放与恢复按钮修复

首次自动播放请求处于等待状态时，`HTMLAudioElement.paused` 可能已经变为 `false`，但 `play()` Promise 尚未成功。旧逻辑据此提前返回“已播放”，导致用户点击“播放/恢复 BGM”时没有发起新的、具备用户激活权限的播放请求；稍后原请求被浏览器策略拒绝，页面仍然无声。

修复位于 `BgmPlayer` 音频所有权层：

- 单独跟踪播放请求是否仍在等待以及请求代次，不再用 `paused` 独自判断播放成功；
- 用户点击恢复时取消旧请求、暂停待定播放并在同一用户手势内重新调用 `play()`；
- 被新请求替代的旧 Promise 不再覆盖当前状态或产生伪错误；
- 音频元素显式启用 `autoplay`，允许支持自动播放的 Wallpaper Engine 宿主直接开始；
- 普通浏览器拒绝有声自动播放时，第一次普通鼠标/键盘交互会自动解锁 BGM，无需执行完整重播。

浏览器回归覆盖三条路径：首次加载显示“等待点击 · 25%”后，点击普通的“显示命中区”即可进入“播放中 · 25%”；重新加载后直接点击“播放/恢复 BGM”同样从 0 秒开始；手动关闭 BGM 后点击该按钮会重新开启并从关闭前进度恢复。控制台未产生音频错误。

## 0.2.5 合并 BGM 控制

“播放/恢复 BGM”与“开启/关闭 BGM”在首次交互自动解锁完成后职责重复，因此从调试面板删除前者。现在只保留一个状态化按钮：播放时显示“关闭 BGM”，关闭时显示“开启 BGM”并在点击后从原进度恢复；“完整重播”继续负责从 0 秒重启。底层 `retryFromUserGesture` 仍保留给首次鼠标/键盘交互和调试 API 使用。
